# 1. Prerequisites

Before learning 0-1 BFS, be comfortable with:

- graphs,
- adjacency lists,
- weighted edges,
- shortest paths,
- normal BFS,
- `queue`,
- `deque`,
- distance array,
- relaxation,
- basic Dijkstra intuition.

Learning chain:

```text
Unweighted BFS
      ↓
Weighted shortest path
      ↓
Weights are only 0 or 1
      ↓
Dijkstra becomes much simpler
      ↓
Use deque
      ↓
0-1 BFS
```

---

## 1.1 Graph Representation

For a weighted graph, store:

```text
neighbor + edge weight
```

Example:

```text
1 --1--> 2
1 --0--> 3
```

Adjacency list:

```cpp
vector<vector<pair<int, int>>> graph;
```

Each pair stores:

```text
{nextNode, weight}
```

---

## 1.2 Distance Array

`dist[v]` means:

```text
best shortest distance currently known
from source to v
```

Initialize:

```text
dist[source] = 0
```

and every other node:

```text
dist[v] = INF
```

Example:

```text
source = 1

dist = [∞, 0, ∞, ∞, ∞, ...]
```

---

## 1.3 Relaxation

Suppose we already know:

```text
dist[u]
```

and there is an edge:

```text
u --w--> v
```

Then a candidate path to `v` is:

```text
dist[u] + w
```

If this is better:

```text
dist[u] + w < dist[v]
```

we update:

```text
dist[v] = dist[u] + w
```

This operation is called:

```text
RELAXATION
```

C++:

```cpp
if (dist[u] + weight < dist[v]) {
    dist[v] = dist[u] + weight;
}
```

This idea is the heart of both:

```text
Dijkstra
0-1 BFS
```

# 2. Shortest Path Reminder

Suppose:

```text
S → A → B → T
```

with weights:

```text
S --1--> A
A --0--> B
B --1--> T
```

Total path cost:

```text
1 + 0 + 1 = 2
```

The shortest path problem asks:

```text
among all possible S → T paths,
find the minimum total edge weight
```

Important:

```text
fewest edges ≠ minimum cost
```

when edge weights differ.

# 3. When Normal BFS Works

Normal BFS is perfect when every edge has the same cost.

Usually:

```text
every edge cost = 1
```

Example:

```text
S --1--> A --1--> C
 \       
  --1--> B
```

BFS processes nodes by layers:

```text
distance 0 → S
distance 1 → A, B
distance 2 → C
```

So normal BFS gives shortest path in:

```text
O(V + E)
```

---

# 4. The 0-1 Weighted Graph

0-1 BFS handles graphs where every edge weight is:

```text
0 or 1
```

Example:

```text
        1
      / | \
    1/  |1 \1
    2   3   4
            |
           0|
            5
```

A zero-weight edge means:

```text
moving through this edge adds no extra cost
```

A one-weight edge means:

```text
moving through this edge increases distance by 1
```

---

# 5. Why Ordinary BFS Fails

Consider:

```text
S --1--> A
|
0
↓
B --0--> C
```

There are two kinds of edges:

```text
cost 0
cost 1
```

Ordinary BFS treats every edge as though:

```text
cost = 1
```

So it orders nodes mainly by:

```text
number of edges taken
```

But we need ordering by:

```text
total path cost
```

These are not always the same.

---

## Small Example

```text
S --1--> A

S --0--> B --0--> C --0--> D
```

Number of edges:

```text
S → A       = 1 edge
S → B → C → D = 3 edges
```

But costs:

```text
cost(S → A) = 1
cost(S → B → C → D) = 0
```

So `D` is actually closer than `A` in weighted distance.

Normal BFS cannot represent this correctly.

---

# 6. Main Observation Behind 0-1 BFS

Suppose we are currently processing node `u`.

Its distance is:

```text
dist[u] = d
```

For an outgoing edge:

```text
u --0--> v
```

new distance is:

```text
d
```

For:

```text
u --1--> x
```

new distance is:

```text
d + 1
```

Therefore newly discovered useful distances are only:

```text
d
or
d + 1
```

This is much more structured than general Dijkstra.

That is why we do not need a priority queue.

---

# 7. Why We Need a Deque

A deque supports:

```text
push_front()
push_back()
pop_front()
```

Rule:

```text
weight = 0
    ↓
push_front

weight = 1
    ↓
push_back
```

Why?

Because a zero-weight transition does not increase distance.

So it should be processed before nodes whose distance increased by `1`.

Diagram:

```text
                     DEQUE

front                                  back
  ↓                                      ↓
[ same distance ][ same distance ][ distance + 1 ]
```

When a `0` edge relaxes a node:

```text
put it near the front
```

When a `1` edge relaxes a node:

```text
put it at the back
```

This keeps processing approximately in nondecreasing distance order.

# 8. Relaxation — The Core Operation

Suppose:

```text
dist[node] = 2
```

and edge:

```text
node --0--> next
```

Candidate:

```text
2 + 0 = 2
```

If:

```text
dist[next] = 5
```

then:

```text
2 < 5
```

so update:

```text
dist[next] = 2
```

Because weight is `0`:

```text
push_front(next)
```

---

For weight `1`:

```text
dist[node] = 2
node --1--> next
```

Candidate:

```text
2 + 1 = 3
```

If better:

```text
dist[next] = 3
```

and:

```text
push_back(next)
```

---

## Core Code

```cpp
if (dist[node] + weight < dist[next]) {
    dist[next] = dist[node] + weight;

    if (weight == 0) {
        dq.push_front(next);
    } else {
        dq.push_back(next);
    }
}
```

This is the central 0-1 BFS pattern.

---

# 9. 0-1 BFS Algorithm Step by Step

Given source `source`:

### Step 1

Initialize:

```text
dist[source] = 0
dist[all others] = INF
```

### Step 2

Create:

```text
deque
```

and insert source:

```text
dq = [source]
```

### Step 3

While deque is not empty:

```text
take node from FRONT
```

### Step 4

For every edge:

```text
node --weight--> next
```

try relaxation:

```text
newDist = dist[node] + weight
```

### Step 5

If improved:

```text
dist[next] = newDist
```

Then:

```text
weight = 0 → push_front(next)
weight = 1 → push_back(next)
```

# 11. Why Push Front for 0 and Back for 1

Suppose current node has:

```text
distance = d
```

For a `0` edge:

```text
new distance = d
```

For a `1` edge:

```text
new distance = d + 1
```

We always want to process smaller distance first.

Therefore:

```text
distance d     → front
distance d + 1 → back
```

Visual model:

```text
Deque:

front
  ↓
[d][d][d][d+1][d+1]
                  ↑
                 back
```

A zero-edge node belongs with the current distance layer.

A one-edge node belongs to the next distance layer.

# 12. Correct C++17 Template

```cpp
#include <bits/stdc++.h>
using namespace std;

const int INF = 1e9;

void zeroOneBfs(int source, const vector<vector<pair<int, int>>>& graph, vector<int>& dist) {
    int n = graph.size() - 1;

    dist.assign(n + 1, INF);

    deque<int> dq;
    dist[source] = 0;
    dq.push_front(source);

    while (!dq.empty()) {
        int node = dq.front();
        dq.pop_front();

        for (auto [next, weight] : graph[node]) {
            if (dist[node] + weight < dist[next]) {
                dist[next] = dist[node] + weight;

                if (weight == 0) {
                    dq.push_front(next);
                } else {
                    dq.push_back(next);
                }
            }
        }
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector<vector<pair<int, int>>> graph(n + 1);

    for (int i = 0; i < m; i++) {
        int u, v, weight;
        cin >> u >> v >> weight;

        graph[u].push_back({v, weight});
        graph[v].push_back({u, weight});
    }

    int source;
    cin >> source;

    vector<int> dist;
    zeroOneBfs(source, graph, dist);

    for (int node = 1; node <= n; node++) {
        cout << dist[node] << ' ';
    }

    cout << '\n';

    return 0;
}
```

If the graph is directed, remove:

```cpp
graph[v].push_back({u, weight});
```

# 13. Why No Visited Array is Needed

In normal BFS we often use:

```text
visited[node]
```

because the first time we reach a node is already optimal.

In weighted shortest path this is not always true.

Example:

```text
S --1--> X

S --0--> A --0--> X
```

We might first see:

```text
dist[X] = 1
```

but later discover:

```text
dist[X] = 0
```

So the important condition is not:

```text
have I visited X?
```

It is:

```text
did I find a BETTER distance for X?
```

Therefore use:

```cpp
if (dist[node] + weight < dist[next])
```

instead of a simple `visited[]` rule.

# 14. 0-1 BFS on a Grid

A grid can be treated as a graph.

Each cell:

```text
(r, c)
```

is a node.

Its neighbors may be:

```text
up
down
left
right
```

So:

```text
(r, c)
   |
   ├── (r-1, c)
   ├── (r+1, c)
   ├── (r, c-1)
   └── (r, c+1)
```

If movement costs are only:

```text
0 or 1
```

then 0-1 BFS is a natural choice.

---

# 15. Application Pattern — Directional Grid

The lecture screenshots show a common pattern:

```text
each cell suggests a direction
```

For example:

```text
→ → ↓
↑ ← ↓
↑ → →
```

Suppose from each cell:

```text
moving in the indicated direction costs 0
moving in another direction costs 1
```

Then each grid cell has up to four outgoing edges.

Example:

```text
current cell says →
```

Moves:

```text
right : cost 0
left  : cost 1
up    : cost 1
down  : cost 1
```

This is exactly a 0-1 graph.

---

## Story → Graph Model

Original story:

```text
move through grid following/changing arrows
```

Remove the story:

```text
each cell = graph node

movement to neighbor = edge

follow preferred direction = weight 0
change direction = weight 1
```

Then ask:

```text
minimum total cost from source cell to target cell
```

Solution:

```text
0-1 BFS
```

---

## Tiny Example

Grid:

```text
→ ↓
↑ →
```

Start:

```text
(0,0)
```

Target:

```text
(1,1)
```

From `(0,0)` arrow is right:

```text
(0,0) → (0,1) costs 0
```

At `(0,1)` arrow is down:

```text
(0,1) → (1,1) costs 0
```

Therefore:

```text
minimum cost = 0
```

No direction change is required.

# 16. Grid C++17 Template

Assume:

```text
grid[r][c] stores preferred direction
```

where:

```text
0 = up
1 = right
2 = down
3 = left
```

```cpp
#include <bits/stdc++.h>
using namespace std;

const int INF = 1e9;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector<vector<int>> grid(n, vector<int>(m));

    for (int r = 0; r < n; r++) {
        for (int c = 0; c < m; c++) {
            cin >> grid[r][c];
        }
    }

    vector<int> dr = {-1, 0, 1, 0};
    vector<int> dc = {0, 1, 0, -1};

    vector<vector<int>> dist(n, vector<int>(m, INF));
    deque<pair<int, int>> dq;

    dist[0][0] = 0;
    dq.push_front({0, 0});

    while (!dq.empty()) {
        auto [r, c] = dq.front();
        dq.pop_front();

        for (int dir = 0; dir < 4; dir++) {
            int nr = r + dr[dir];
            int nc = c + dc[dir];

            if (nr < 0 || nr >= n || nc < 0 || nc >= m) {
                continue;
            }

            int weight = (grid[r][c] == dir ? 0 : 1);

            if (dist[r][c] + weight < dist[nr][nc]) {
                dist[nr][nc] = dist[r][c] + weight;

                if (weight == 0) {
                    dq.push_front({nr, nc});
                } else {
                    dq.push_back({nr, nc});
                }
            }
        }
    }

    cout << dist[n - 1][m - 1] << '\n';

    return 0;
}
```

# 17. Multiple Sources / Components Idea

The screenshots also illustrate thinking in terms of zero-cost regions/components.

Suppose many nodes are connected through:

```text
weight 0
```

Example:

```text
A --0-- B --0-- C
```

Moving anywhere inside this zero-cost region does not increase distance.

Conceptually:

```text
A, B, C
```

behave almost like one distance layer.

That is why 0-1 BFS aggressively processes zero-weight edges from the front.

Visual:

```text
distance d:

A --0-- B --0-- C
                  \
                   1
                    \
                 next layer d+1
```

You do **not** need to explicitly contract zero-weight components for standard 0-1 BFS.

The deque behavior handles them automatically.

# 18. 0-1 BFS vs BFS vs Dijkstra

## Normal BFS

Use when:

```text
all edges have equal weight
```

usually:

```text
weight = 1
```

Data structure:

```text
queue
```

Complexity:

```text
O(V + E)
```

---

## 0-1 BFS

Use when:

```text
every edge weight is 0 or 1
```

Data structure:

```text
deque
```

Complexity:

```text
O(V + E)
```

---

## Dijkstra

Use when weights are non-negative but may be:

```text
0, 1, 2, 7, 100, ...
```

Data structure:

```text
priority_queue
```

Typical complexity:

```text
O((V + E) log V)
```

---

## Decision Table

| Edge Weights | Algorithm |
|---|---|
| all equal / unweighted | BFS |
| only `0` and `1` | 0-1 BFS |
| arbitrary non-negative | Dijkstra |
| negative edges | Bellman-Ford / other appropriate technique |

# 19. Connection to Dial's Algorithm

The lecture also connects this idea with bounded integer edge weights.

0-1 BFS is a very special bucket-based shortest path algorithm.

For weights:

```text
0 or 1
```

we only need two effective distance levels:

```text
current distance
current distance + 1
```

A deque is enough.

For small bounded integer weights:

```text
0 ... K
```

a more general bucket idea leads toward:

```text
Dial's Algorithm
```

Mental progression:

```text
BFS
weights all 1
      ↓
0-1 BFS
weights 0/1
      ↓
Dial-style buckets
small bounded integer weights
      ↓
Dijkstra
general non-negative weights
```

Do not use Dial's algorithm automatically.

For competitive programming:

```text
weights only 0/1
→ 0-1 BFS is usually the cleanest choice
```

# 20. Complexity

Let:

```text
V = number of vertices
E = number of edges
```

Each successful useful relaxation may place a node in the deque, and with 0/1 weights the total processing remains linear in the graph size.

Standard complexity:

```text
Time = O(V + E)
```

Space:

```text
adjacency list = O(V + E)
distance array = O(V)
deque          = O(V)
```

Total:

```text
Space = O(V + E)
```

For an `N × M` grid:

```text
V = N × M
```

Each cell has at most four edges, so:

```text
E = O(N × M)
```

Therefore:

```text
Time = O(N × M)
Space = O(N × M)
```

# 21. Common Mistakes

| Mistake | Correct Idea |
|---|---|
| Using normal BFS for 0/1 weights | Use deque-based 0-1 BFS |
| Using `queue<int>` | Use `deque<int>` |
| Pushing every relaxed node to back | `0 → front`, `1 → back` |
| Marking node permanently visited on first sight | Use distance relaxation |
| Forgetting `INF` initialization | All non-source distances start large |
| Relaxing with `dist[next] + weight` | Use `dist[node] + weight` |
| Using 0-1 BFS when weight can be 2, 5, 10... | Use Dijkstra or suitable bucket algorithm |
| Treating grid separately from graphs | Each cell is simply a node |
| Forgetting direction for directed graph | Add only the correct directed edge |
| Reprocessing without checking improvement | Push only after a successful relaxation |

# 22. Recognition Model

When a problem says:

```text
edge cost is 0 or 1
free vs paid move
same color costs 0, change costs 1
preferred direction costs 0
changing direction costs 1
teleport costs 0
normal move costs 1
reverse an edge at cost 1
minimum number of changes
minimum number of reversals
minimum walls broken where empty=0 and wall=1
```

think:

```text
0-1 BFS
```

The recognition question is:

```text
Can every transition be classified as:

FREE  → cost 0
PAID  → cost 1
```

If yes, 0-1 BFS should be one of your first thoughts.

# 23. Final Mental Model

Do not memorize 0-1 BFS as just code.

Understand this:

```text
Dijkstra says:
always process the smallest distance next
```

With only 0/1 edges, from current distance `d` we create only:

```text
d
d + 1
```

So we can maintain the order using a deque:

```text
0-edge → same distance → FRONT
1-edge → next distance → BACK
```

Final picture:

```text
                 edge weight
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
          0                     1
          │                     │
          ▼                     ▼
   distance unchanged     distance + 1
          │                     │
          ▼                     ▼
     push_front()           push_back()
          └──────────┬──────────┘
                     ▼
               process front
                     │
                     ▼
              shortest paths
```

The core code to remember is only:

```cpp
if (dist[node] + weight < dist[next]) {
    dist[next] = dist[node] + weight;

    if (weight == 0) {
        dq.push_front(next);
    } else {
        dq.push_back(next);
    }
}
```

And the core recognition rule is:

```text
0/1 edge weights
      ↓
0-1 BFS
      ↓
deque
```
